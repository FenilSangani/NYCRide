    Uber vs Lyft

    There is no city-wide winner. Across 13,617 routes with enough solo trips on both in the test month, Lyft priced above Uber on 67% of them, and the middle 80% of routes ran from Lyft 14% dearer to Uber 14% dearer. Which one is cheaper is a per-route question.

    The model learned that rather than a flat discount: on the same routes it puts Uber dearer 32% of the time against a measured 33%.

    Uber is 72.7% of the trips read, Lyft 27.3%.

    Why this is limited

    The trip records give a zone, never a street address — the TLC drops exact coordinates for privacy. So "walk a bit" can only mean "start from the next zone", and on the measured sample only about half of trips had a neighbouring zone close enough for that to be worth it.

    Weather

    Tested and dropped

    Hourly weather was joined to every trip and fed to the model. It did not earn its place.

    Rain, September

    Model error with it
    +$0.01

    Rain really does lift the citywide mean fare 5–6% in September and April. But when temperature, rainfall and wind were added to the model as features, the error on the unseen month moved from $5.080 to $5.089 and R² from 0.799 to 0.794 — slightly worse. The lift is already carried by hour and zone, which the model has. So the feature is not used. A feature that only sounds good is still a feature that does nothing.

    The demand figure the map shows is the average, not the model. With live lag features the model wins at 0.972, but a static site has no live feed, and without lags it scored below the plain average. So the average ships.

    What the model leans on

    Permutation importance: each feature is shuffled in turn and the drop in accuracy is measured. Distance dominates, which is what you would hope — the rest is the model learning that the same mile costs differently by place and hour.

    How it was built

    Trained on months, tested on a later one. A random split would let the model see the future and report a score it could not repeat in use.
